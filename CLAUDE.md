## Правила (строго)

1. **Никаких изменений без «да».** Сначала коротко: что изменится и зачем. Ждём «да» — потом делаем.
   Касается и исправлений, которые нашёл сам.
2. **Ядро не знает клиентов.** В `core/` и `modules/` нет ни имён людей, ни названий фирм, ни их правил,
   ни «если клиент такой-то». Всё конкретное — в `clients/<клиент>/`. Хочется написать в ядре условие
   про конкретного клиента — значит, нужен крючок (hook) в ядре и правило в папке клиента.
3. **Код живёт в git.** GitHub `fwjn7w7cng-cloud/kpi-platform`, ветка `main` = рабочее состояние.
   Правка: ветка → тесты → fast-forward в `main` → push. Никогда `push --force` в `main`.
4. **Тесты перед каждым пушем.** `python3 -m unittest discover -s tests -v` — всё зелёное.
5. **Секреты не в git.** Токены ботов, ключи Google, пароли — только в `.env` клиента на сервере.
   Не выводить в чат, не просить Адама вставлять их в чат.
6. **Журнал `JOURNAL.md` обязателен.** Перед работой — прочитать верхние записи и `git log --oneline -10`.
   После заметной работы — запись сверху: дата и время по Москве, кто, 1–3 строки (что сделано, что найдено,
   что осталось). Это единственный мост между Джарвисом и Альфредом.

## Кнопки, окна и стрелка (Адам 31.10 — правило для всего приложения)

- **Где на одном листе несколько вариантов и надо выбрать — окно:** варианты ☑ / ☐ (или ● в «таблетках»), внизу
  `ok_row(prefix)` — «✅ ОК» (`<prefix>:ok`) / «✖️ Отмена» (`<prefix>:no`). До «ОК» меняется только черновик в сессии.
  Где просто нажал и вошёл — без «ОК». Выбор одного из списка — `core/ui/pick.one` (готовое окно).
- **Стрелка «‹ Назад» есть везде и ведёт ровно на прошлый экран.** `core/app.press`: окно (`window_of`) — один шаг в пути,
  галочки внутри шагов не добавляют, «ОК» / «Отмена» убирают окно из пути; `REPLACE` — вкладки одного экрана; `STEPLESS` —
  вопросы теста (стрелка — к списку тестов).
- Необратимое («Утвердить месяц» `monq`, «Провести приказ» `hrq`, «Отменить процесс» `hrz`, «Выключить Рамадан» `rmq`,
  «Уволить») — сначала «Точно?» с «ОК / Отмена».
- **Пояснение ⓘ у каждой настройки** (Адам 31.10: «не текстом внизу, а иконкой i рядом»): `Button(..., info="…")` — в приложении
  справа значок ⓘ, нажатие открывает листок с объяснением и кнопку не нажимает. Пояснения: функции — `screens.LOCK_TEXT`,
  блоки / варианты / поля конструктора зарплаты — `paybuilder.VARIANT_INFO` / `BLOCK_VARIANT_INFO` / `FIELD_INFO`.
- Окно набора (`swe`): набор — один; отделы галочками (включил — все функции отдела, выключил — снялись), под отделом — его
  функции с ценой и «👥 Людей в отделе»; галочка не уводит страницу наверх, итог виден над «ОК».
- Проверка: `python3 tools/nav_check.py` — робот проходит все роли демо (около 1 400 экранов): экран открылся, стрелка —
  на прошлый экран, «Отмена» — туда же, выбор без «ОК» — ошибка. Входит в тесты (`tests/test_navigation.py`).

## Как подключить нового клиента

1. **Анкета в приложении → «🚀 Создать клиента»** (Адам 31.10, `core/onboard.create`): админ в анкете клиента («🛠 Пульт → 📋 Анкеты»)
   жмёт кнопку — бот сам делает `clients/<код>/` из `_template`, пишет `config.yaml` по анкете (пакеты, отделы, должности, выходные,
   схемы зарплаты по вариациям конструктора — **цифры стандартные, уточнить с клиентом**) и `.env` (WEB_PORT — следующий свободный
   после 8101, WEB_URL `https://<код через дефис>.<домен демо>`, WEB_ADMIN_KEY случайный). Код клиента — `anketa.slug` от названия;
   занят — не создаёт. Экран «🚀 Что дальше» (`cdw`) — шаги и фраза Альфреду; «🔑 Ссылка администратора» (`cdk`) — вход `…/?admin=<ключ>`
   (ключ хранится и в карточке `client_cards[..].client`). Запасной путь — таблица: `python3 tools/anketa.py blank шаблон.xlsx` /
   `check` / `apply <файл|ссылка>` (`core/anketa.py`), «📥 Анкета Excel» в карточке.
2. **Альфред** (одна просьба Адама): `chown -R alapa:alapa /srv/alapa`, `systemctl enable --now kpi-web@<код>`, адрес в Caddy (`<код>.alapa.pro → reverse_proxy
   127.0.0.1:<WEB_PORT из .env>` + `import secure` + `request_body { max_size 24MB }`), службу в journalmatch jail `alapa-web`, проверить, что открывается, **закоммитить `clients/<код>/` в `main`** (`.env` в git не попадает —
   `*.env` в .gitignore) и записать в журнал.
3. Переводчик `parser.py` — по 2–3 файлам его 1С; проверка: `python3 tools/check_client.py <код> файлы…`.
4. Своё, чего нет в ядре, — только в `rules.py` через крючки (`core/hooks.py`), ядро не трогаем.
6. **Отчёты без кнопки (31.10):** у каждого настоящего клиента своя папка — бот раз в 10 минут забирает файлы из
   `data/<код>/inbox/` (`core/ingest/folder.py`, `core/jobs/worker.py`), автоматически — правила конвейера (месяц на согласовании —
   только кнопкой), журнал «🧪 Что пришло» (who «автоматически»), админам «📬 Новые отчёты 1С» лентой и 🔔. Как файлы попадают в папку —
   **основной путь — «🔌 Связь с 1С» (Адам 31.10: «выгрузка прямо в приложение, как на Google Диск»):** сетевая папка (подключить
   как диск Windows на компьютере с 1С, выгрузка 1С по расписанию — туда) или прямая отправка из 1С программистом; инструкция PDF для
   клиента — в приложении. Запасные: почта (`kind: mail`), курьер rclone. Caddy пропускает к приложению все методы (WebDAV) — проверить.
   Уведомления: на iPhone — только из приложения на экране «Домой» (iOS 16.4+). В демо фоновой работы и уведомлений нет.
5. **Сотрудники и вход (31.10, `core/people.py`):** по ссылке администратора Адам (или директор, или назначенный админ клиента —
   сотрудник с ролью «Администратор», `ctx.admin`) открывает «👥 Сотрудники и доступ» (`pa`, внизу у админа; у директора и начальника —
   на главной): ➕ добавить (`pad` → имя → должность → команда), 🔗 пригласить (`pai`: одноразовая ссылка `WEB_URL/?start=<код>`,
   `INVITE_DAYS` 7; вход — `people.redeem` в `App.start`, устройство привязывается к сотруднику через `employees.tg_id`; новая ссылка —
   новое устройство, старое теряет вход), 🚫 закрыть доступ (`pax`), 🗑 уволить / ↩️ вернуть (`paf`), ✏️ должность (`pap`), 👥 команда
   (`pat`), 🎚 роль (`par`, только админ и директор), 🧾 «Нет в расчёте» (`pak`: имя из 1С → человек или новый торговый). Начальник отдела —
   только свой отдел. Гость без приглашения видит «вас пока нет в списке» + запасной путь «напишите фамилию» (`regs`). В демо экраны есть,
   ссылки не выдаются. Telegram-вариант (`kpi@<код>`, BOT_TOKEN в `.env`) остаётся на случай, если клиенту нужен мессенджер.

## Пакеты, наборы и модули (конструктор — решение Адама 30.10)

Бот собирается по отделам, а не одной «редакцией» (`core/access/editions.py`): пакеты 📈 `sales` (уровни Старт / Бизнес /
Премиум), 📦 `stock` (склад и закупки), 🚚 `logistics`, 👤 `office` (кадры и офис), ⭐ `max` (бренд, филиалы,
функции на заказ). Клиент берёт нужные пакеты — на всю фирму или на часть отделов; **размер фирмы на доступ не влияет, только
на цену**. Готовые наборы `PRESETS` (по привычке «редакции»): Старт / Бизнес / Премиум — только продажи; Компания — все четыре
отдела; Максимум — всё. В анкете: `edition` (готовый набор) и/или `packages: {sales: business, stock: true, …}`; старые
`addons` понимаются (модуль → его пакет). `cfg.packages`, `cfg.modules`, `cfg.dept_on(отдел)` — куплен ли пакет отдела:
сотрудник неподключённого отдела видит «отдел пока не подключён», у директора кнопка отдела — с замком.

**Цены — за функции (Адам 31.10):** отдел — папка, платим только за функции (`editions.FUNCS`: код → отдел, цена; короткие
имена `FUNC_SHORT`), настройки внутри функции — бесплатно; бесплатно у всех — напоминания, журнал, кабинеты (`FREE`).
«💰 Зарплата» — одна функция для всех отделов: табель, оклад, сдельная, ГСМ, бонусы, штрафы (в общую сумму). Цены `f_<код>` +
`user` 300 ₽ за человека; скидка −15 % за все 4 отдела — на функции и людей, дополнительное (бренд, филиалы, на заказ) без скидки.
Наборы = стартовые функции + люди + роли по размеру фирмы (`preset_functions`, `SIZES`); у клиента — `functions:` в анкете
(важнее пакетов, `cfg.with_functions`), в демо — `session["funcs"]`; связи функций — `toggle_function` (`REQUIRES`).
Итог по умолчанию: Старт 9 800, Бизнес 19 500, Премиум 31 000, Компания (63 чел.) 45 000, Максимум (127 чел.) 106 300 в месяц.
Оплата (предложено Адаму 31.10): подключение 50 % при договоре и 50 % при запуске; пробные 14 дней от запуска; первый счёт —
остаток месяца пропорционально дням; дальше счёт 1-го, оплата до 5-го; 6-го напоминание, 10-го — «только смотреть», 15-го —
отключение, данные 3 месяца. Прежнее ниже — про пакеты (их код остался для совместимости).

**📄 Правила и оплата (Адам 01.11, `core/billing.py`, экран `bl`; директор, админ клиента; в демо тоже). Договора и подписей нет — «Правила
предоставления услуг», вместо «подписали» — «договорились» (`contract` в базе = день, когда договорились):** порядок оплаты утверждён Адамом —
договор (½ подключения) → запуск (½) → 14 дней бесплатно с запуска → 15-й день счёт за остаток месяца по дням, оплата за 5 дней
(хвост ≤ 3 дней — в счёт 1-го) → дальше 1-го, до 5-го; неоплата: срок +1 напоминание, +5 только просмотр, +10 отключение (пока только текстом —
бота не выключает, решает Адам). Плашка на главной (`home_line`). **Добавить / убрать функции и людей — только с одобрения Адама:** окно `blc`
(галочки функций, люди ±1/±10, «Счёт <дата>, итого» + «Сейчас за остаток месяца» + «С <месяца> каждый месяц», «ℹ️ Почему так») →
заявка админам `bly` ✅ / `bln` ❌ с причиной (`bl_no`) → одобренное: `billing.functions` перекрывает анкету (`core/ui/context`),
доплата за остаток месяца — строкой в следующем счёте (`extras`), люди — лимит `billing.people` (сверх — «➕ Добавить сотрудника» не пускает).
Даты и оплаты Адам ставит сам: «🛠 Даты и оплата» `blm` (договор / запуск сегодня, ✏️ даты, «✅ Оплачено всё» / «✏️ Оплачено частично» —
сумма в `got`, клиент видит остаток, шаги 6/10/15 — от остатка; «↩️ Снять последнюю отметку» по `marks`). **Без реквизитов, способов оплаты,
имён и телефонов** (Адам 01.11), способ оплаты не упоминаем. PDF: правила `bld`
(простыми словами, Docs-артефакт 8JHjxf6K1NPJTh5y3BNTFS), порядок оплаты `blo` (Docs E1xr3EwADGZPxpwkQfRjSZ). Демо: договор 14 дней
назад, запуск 10 дней назад, пометка «Пример: даты и суммы выдуманы», дни листаются «◀ неделя / 📅 Сегодня / неделя ▶» (`blt`,
`session.bl_shift`, `billing.today_`); заявку зритель одобряет сам «🎭 Одобрить (в демо — вы за нас)». В текстах для клиента — «мы», не «Алапа» (Адам 01.11: склонение звучит непонятно). Тексты договора и порядка оплаты
(Адам 01.11, «без мелкого шрифта») — `billing.LEAD` / `CONTRACT` / `ORDER_RULES` / `LATE`, те же, что в Docs-документах; график — дата
крупно, что это — целиком под ней (`sched_rows`). Старый `tfr` — окно `blc` с отмеченной функцией.
**Ограничения при неоплате — сами (Адам 01.11, вариант А):** `billing.level` ok / remind / view (срок +5) / off (срок +10); `billing.gate`

(код клиента → карточка, код товара → остаток). Сдельные кубики зарплаты `per_unit` — единицы регистрирует модуль

Тяжёлые расчёты между нажатиями — `app.memo(ctx, имя, fn)`: живёт, пока не поменялись данные (`db.rev()`).
Главная длиннее 12 кнопок — в группы (`screens.MENU_GROUPS`, экран `mg:<группа>`); новый пункт меню — добавить его в группу.

## Показ (демо)

`source.kind: seed` — режим показа: у каждой отрасли своя база (`data/<клиент>/<отрасль>/kpi.db`),
наполняется `clients/<клиент>/seed.py`, обновляется сама в начале месяца. Зритель кнопками внизу главной
выбирает роль (продажи и руководство — ролью, остальные отделы — должностью `sw:pos:<должность>`, или конкретного
человека), отрасль (8) и собирает набор пакетов с ценой («🧩 Собрать», готовые наборы — кнопками); «Начать демо заново» —
свежие цифры. **Демо по умолчанию — «Компания»** (Адам 31.10: средняя фирма, все отделы — сразу показывать; «Максимум» —
галочкой). Готовые наборы — **по размеру фирмы, только по умолчанию** (`editions.SIZES`: Старт — до 10 человек, Бизнес —
10–25, Премиум — 25–50 в продажах, Компания — 50–100 все отделы, Максимум — 100+ и филиалы): при выборе набора люди по
отделам ставятся типовые; любой фирме можно любой набор, дальше всё настраивается индивидуально. Пакеты, уровень, наборы,
«за год» — окно «☑️ Выбрать пакеты» (`swe`), отрасль — окно `swi`. Всё «для нас» — внизу отдельной кнопкой «🛠 Пульт» (`adm`, только настоящий админ по WEB_ADMIN_KEY): пригласить клиента,
добавить партнёра, 👥 гости, 🤝 партнёры, 📨 заявки «Хочу так» (`rqs`), 💰 цены, 📘 памятка.
Партнёры (Адам 30.10, `core/demo.py`): показывают демо клиентам со своего телефона. Админ: «🛠 Пульт → 🤝 Добавить
партнёра» — одноразовая ссылка, доступ без срока (till 2999-12-31), пока админ не отключит. Партнёр: всё демо,
«🔄 Заново», «🤝 Мои клиенты» (`ptn`: свои приглашения клиентам — клиент закрепляется `by`, продлить / отключить только своих,
анкеты своих клиентов), «📘 Инструкция» (`ptm`, PDF `ptp`; текст — `demo.MEMO`, это инструкция по боту; общая памятка «что это
и что делать» — документ для отправки, Docs-артефакт WLG23xzEedNBPqZ8wUcBdq). «📨 Хочу так» у партнёра спрашивает клиента и
заводит ему карточку `<партнёр>c<n>`; заявка клиента партнёра приходит и партнёру. Цены партнёр не правит, чужих гостей не видит.
Инструкция админа — «🛠 Пульт → 📘 Моя инструкция» (`adi`, `demo.ADMIN_MEMO`).

Анкета клиента в боте (Адам 30.10, `core/onboard.py`, ключ `client_cards` в базе офиса): группы «Компания», «Контакты», «1С и
отчёты», «Особенности», «Старт» (`GROUPS`: поле, подпись, text/choice, обязательное); снимок конструктора `set` (пакеты, люди,
суммы, `pay` — вариации «💵 Как платите торговым» из `sw:pay`: оклад / % / бонус за план none-fix-steps-linear / АКБ / просрочка /
водителям сдельно / складу без ошибок / «по-другому» текстом) обновляется, когда клиент открывает свою анкету или жмёт «Хочу так».
`flags()` — ⚠️ нестандарт (не 1С, филиалы, зарплата по-своему…) — подсказка нам о настройке / доработке. Экраны `cd[:id]`, `cdg`,

стандартными цифрами). Видят: клиент — свою (кнопка на главной гостя и в конструкторе), партнёр — своих, админ — все.

## Данные (`core/data`)

- База клиента — `data/<клиент>/kpi.db` (`client_db_path`, папку переносит `KPI_DATA`). `DB.open` сам догоняет миграции.
- Миграции — `core/data/migrations.py`: список только дописывается в конец, старые шаги не трогаем.
- Факты (`sales`, `debts`, `payments`, `visits`, `returns`, `stock`, `item_sales`, `trips`, `trip_stops`, справочники
  `clients`, `groups`) пишутся только **пачками**
  (`DB.load(Dataset)`): новая пачка того же вида за тот же период заменяет прежнюю; файл с тем же
  `fingerprint` повторно не принимается; строка с датой вне периода — вся пачка отклоняется.
- Люди в фактах — ключом источника (`emp_key`, «фамилия имя», `norm_key`: регистр, ё, пробелы).
  Ключ → сотрудник в `emp_keys` с датой `since`: новый торговый на старой территории — `bind_key(…, since=…)`,
  продажи до даты остаются прежнему. Не привязанные ключи — `unknown_keys()` («нет в расчёте»).
- Месяц: `open` → `review` → `approved` (`set_month_status`, пишет в `audit`).
- Дебиторка: корзины 0–30/31–60/61–90/91+ и необязательное `over` (готовая просрочка сверх порога из 1С);
  `Kpi.overdue_amount(строка, дней)`, `Kpi.debt_share(люди, дней, база)`; норма и база — `kpi.debt_norm`, `kpi.debt_base`.
